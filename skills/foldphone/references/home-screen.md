# 홈 화면(One UI 런처) 정리 — `phone-home`

> 2026-09-23 실측. 커버 6페이지 → 2페이지, 메인 3페이지 → 1페이지로 정리하면서 밟은 것 전부.
> 코드 `cli/phone-home` (+ `cli/launcher-ocr.swift`, 첫 실행 때 `~/.cache/phone-home/ocr` 로 빌드)

## 무엇으로 되나 — 경로 3개

| 하고 싶은 것 | 되는 경로 | 안 되는/주의 |
|---|---|---|
| 새 폴더 | 아이콘 길게 → **「선택」** → 여러 개 체크 → 상단 **「폴더 추가」**(`multi_select_create_folder`) | 폴더는 **마지막으로 선택한 아이콘 자리**에 생긴다. 선택은 페이지를 넘겨도 유지 |
| 기존 폴더에 추가 | 폴더 열기 → **⊕(`add_apps`)** → 검색 → 체크 → 완료 | ⚠️ **옮기는 게 아니라 복사**다. 홈 원본이 그대로 남는다 → 선택 모드 「홈에서 삭제」로 따로 뺀다. 이미 그 폴더에 든 앱은 검색에 **안 나온다**(«검색 결과 없음») |
| 이름 | 폴더 열기 → `folder_title` 탭 → **Ctrl+A**(`input keycombination 113 29`) → 붙여넣기 | `adb input text` 는 한글 불가 → `clip2phone "이름"` + `KEYCODE_PASTE(279)` |
| 폴더에서 빼기 | 폴더 안 아이콘 길게 → 「홈에서 삭제」 | 바로가기만 없어지고 앱은 남는다 |
| 배치 옮기기 | **평소 모드에서 하나씩** 끌기(`input motionevent DOWN/MOVE/UP`) | 🚨 **여러 개 선택해서 끌면 페이지가 안 넘어간다**(커버·메인 둘 다, 가장자리 대기·흔들기 모두 실패). 같은 페이지 안에서는 된다 — 선택한 **순서대로** 떨어뜨린 칸부터 채운다(순서 정렬에 유용) |
| 빈 페이지 삭제 | **빈 칸**을 길게 → 편집 모드 → 페이지 카드의 삭제 버튼 | 아이콘이 있는 페이지를 지우면 **아이콘도 같이 사라진다** → 가운데 페이지의 아이콘 0개를 확인한 뒤에만 |

## 🚨 안전 — 팝업의 위험 버튼

길게 누른 팝업 맨 아래 줄: **「선택 · 홈에서 삭제 · 설치 삭제 · 위젯」**(시스템 앱은 「설치 삭제」 대신 **「사용 중지」**). 버튼 간격 약 160px.

1. **팝업은 `uiautomator dump` 에 안 잡힌다**(애니메이션 중 `could not get idle state` → 옛 화면이 덤프된다). → **스크린샷 + Vision OCR** 로 글자 위치를 찾는다.
2. **좌표를 추정해서 누르지 말 것.** 앱마다 팝업 높이가 다르다 — 메시지 아이콘 팝업엔 「메시지 작성」·**연락처 바로가기(전화번호)**가 끼어 있어, 고정 오프셋 탭이 전화로 갈 수 있다(실제로 한 번 빗나갔다. 사후 `dumpsys usagestats` 로 아무 앱도 안 열렸음을 확인).
3. 누르기 조건: 원하는 버튼이 **정확히 1개** + 「홈에서 삭제」와 **같은 줄** + 「설치 삭제/사용 중지」와 **떨어져 있음**. 아니면 BACK.
4. OCR 오독이 있다(「홈에서 삭제」→「홈에서 **삭저**」) → 접두어 `홈에서 삭` 로 매칭. 위험 버튼 쪽 판정은 반대로 넓게.
5. 선택 모드 상단 툴바는 **resource-id 로** 누른다: `multi_select_remove_shortcut`(홈에서 삭제) · `multi_select_create_folder`(폴더 추가). 옆의 `multi_select_uninstall`(사용 중지/설치 삭제)과 헷갈리지 않게 **id+text 둘 다** 확인.

## 덤프 읽기 함정

| 증상 | 원인 · 처방 |
|---|---|
| 선택했는데 「선택 안 됨」으로 읽힘 | 덤프가 늦게 따라온다. 0.8초 뒤 **한 번 더 읽고** 판정. 섣불리 재탭하면 **선택이 풀린다** |
| 없는 페이지에서 아이콘이 «보임» | 선택/편집 모드는 옆 페이지를 가장자리에 **1px** 걸쳐 덤프한다 → **폭 >100px** 필터 |
| 폴더 내용 목록에 배경 아이콘이 섞임 | 폴더 팝업 뒤 홈 아이콘도 덤프된다 → `add_apps` 노드 **이후**의 `icon_container` 만 |
| 선택 모드 좌표로 떨어뜨렸는데 한 줄 아래 | 선택 모드는 격자가 **축소**되지만, 끄는 동안엔 **원래 크기**로 돌아온다 → 드롭 좌표는 **평소 모드 격자** 기준 |
| 페이지 표시가 계속 «6 페이지 중 2» | `wsCellLayoutContainer` 의 content-desc 는 갱신이 늦다. 페이지 판별은 **아이콘 집합**으로 |
| 캡처가 PNG 가 아님 | 디스플레이 2개 → `screencap -d <id>`. 포트 147=메인, 148=커버 (`dumpsys SurfaceFlinger --display-id`) |

## 화면별 격자 (Galaxy Z Fold 8 실측)

| | 커버(접힘, state 0) | 메인(펼침, state 3) |
|---|---|---|
| 해상도 | 1248×1972 | 1848×2448 (세로) |
| 격자 | 4×5, 칸 283×278 | 5×8, 칸 307×239 |
| 독 | 5 | 6 |

- **펼침·접힘은 사람만 바꿀 수 있다.** 두 화면의 홈 배치는 **따로**다(커버 화면 미러링 꺼짐 상태).
- 이번 설계: 커버는 1p=자주 쓰는 앱, 2p=폴더 12개(첫 줄 비움 → 엄지 높이). 메인은 1p 하나에 2~4행 앱 / 5행 비움 / 6~8행 폴더.

## 권장 순서

1. `phone-home ls --folders` 로 현재 상태 → 분류안을 사용자에게 승인받는다(삭제 없음을 명시)
2. `folder` 로 새 폴더들 → 기존 폴더는 `add`(자동으로 홈 원본 제거) → `rename` → `pull`
3. 배치: 같은 페이지 안 정렬은 선택 순서 드롭, 페이지 간 이동은 `move`(하나씩)
4. `drop-empty-pages` → 마지막에 `ls --folders` 로 **목표 목록과 전량 대조**(말로 «됐다» 금지)
